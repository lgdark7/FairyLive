## Phase 4 Scope & Priorities: Real-Device Overlay QA & Broadcast Fidelity

### Objective
Make the overlays feel production-grade on an actual physical Android device, not just mathematically correct in tests/emulator captures.

### Priority Directives
1. **P0 — Physical-Device Validation & Broadcast Fidelity**:
   - Verify on physical device (Google Pixel 6a / Pixel 8).
   - Real YouTube Live broadcast confirmation.
2. **P0 — Complete 10-Overlay Type Matrix**:
   - Test every overlay type: `TEXT`, `IMAGE`, `GIF`, `FACECAM`, `ALERT`, `QR`, `LOWER_THIRD`, `GOAL`, `WIDGET`, `YOUTUBE_SUBSCRIBER`, `WEB`.
   - Verify visual equivalence across:
     - Creator Studio Preview
     - GLES Compositor
     - RTMP / YouTube Output
3. **P1 — Gesture Torture Testing**:
   - Rotate, scale, crop, and drag under rapid touch events without crashes, coordinate drift, or bounding box detachment.
4. **P1 — Web Overlay Browser Source Stress**:
   - Webpage internal zoom vs overlay scale.
   - Smooth touch scrolling, HTTPS rendering, transparent backgrounds.
5. **P2 — Performance Metrics**:
   - Monitor frame rate, encoder queue drops, memory consumption, and <= 2 hardware codecs.
6. **Freeze Rule**:
   - NO new overlay types, NO new major UI features, NO backend rewrites.
   - Strictly: Reproduce → Identify Root Cause → Fix → Regression Test → Real Device Verification.
