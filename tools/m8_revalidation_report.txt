### 1. A/V TIMESTAMP SYNCHRONIZATION & ROOT CAUSE ANALYSIS

#### Root Cause of Previous ~6.5s Audio Span Drift:
In earlier implementations, `AudioCaptureEngine` derived audio presentation timestamps (PTS) using system wall-clock elapsed time rather than strict continuous sample-clock progression (`totalBytesCaptured / (sampleRate * channelCount * bytesPerSample)`). Under emulator thread scheduling and CPU preemption during GLES rendering, system monotonic time drifted relative to the actual PCM audio buffer accumulation. Furthermore, during mute, buffers were omitted rather than filled with zeroed PCM, creating timeline discontinuties.
**Engineering Fix:**
1. `AudioCaptureEngine`: Implemented exact continuous sample-clock accumulation: `ptsUs = (totalPcmBytes * 1_000_000L) / (SAMPLE_RATE * CHANNELS * BYTES_PER_SAMPLE)`.
2. Mute handling preserves continuous timeline: zeroed PCM bytes are fed to `MediaCodec` without dropping audio chunks.
3. Added diagnostic telemetry: `capture.pcmDropped`, `encoder.inputTimeout`, `queueDropped`.

### 2. REAL ACTIVE GIF FPS & COMPOSITOR DUP-SUPPRESSION TEST

- **Engine Implementation:** `GifStreamPlayer` utilizes Android `android.graphics.Movie` decoding onto exactly one reusable `Bitmap`. `getFrame(config, streamTimeMs)` calculates movie progress: `relTime = (streamTimeMs % duration)`. If `relTime != lastFrameTime`, it renders the new frame onto the single Bitmap and returns `Pair(bitmap, true)` (`frameChanged = true`). If unchanged, it returns `Pair(bitmap, false)`.
- **GLES Optimization:** In `GlesRenderer.kt`, texture re-upload (`glTexSubImage2D`) for GIF layers is strictly gated on `gifFrame.second == true`. Static overlays upload once upon allocation; animated GIFs only upload when the animation frame index actually advances.
- **Compositor Duplicate Suppression:** `OverlayCompositor` runs a 240 Hz poll loop paired with `SurfaceTexture.OnFrameAvailableListener`. If `surfaceTexture.timestamp == lastCaptureTimestampNanos`, the loop increments `duplicateRendersSkipped` and yields immediately without swapping buffers or triggering MediaCodec.

### 4. TEXTURE MEMORY ACCOUNTING & REAL BUDGET

- **Memory Accounting Added (`OverlayResourceManager.kt`):**
  Added thread-safe `TextureMemoryStats` structure tracking:
  * `activeTextureBytes`: Sum of raw pixel memory (`width * height * 4`) for all currently retained OpenGL ES textures.
  * `cachedBitmapCount`: Number of rasterized Bitmaps in the LRU cache.
  * `totalAdmittedBitmaps`: Monotonic allocation counter.
  * `evictionCount`: Explicit counter incremented whenever an entry is evicted to stay within budget.
  * `largestBitmapBytes`: High-water mark of single texture allocation.
- **Enforced Budget:** `CompositorLimits.MAX_TEXTURE_MEMORY_BYTES = 24 MiB` (25,165,824 bytes).
