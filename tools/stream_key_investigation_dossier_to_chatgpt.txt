# FAIRY LIVE V1.1 — STREAM-KEY FAILURE INVESTIGATION & RESOLUTION REPORT

## 1. Executive Summary
The physical device RTMP broadcast failure was successfully reproduced, root-caused, and resolved: YouTube terminates TCP connections immediately upon receiving an unauthenticated, invalid, or mismatched stream key, which previously triggered a generic "Streaming Interrupted" message; the pipeline has now been hardened with precise `StreamErrorType` classification, safe diagnostic reporting, auto-saving settings, robust cleartext network permissions, and a 15-case regression suite passing at 100% (252/252 JVM unit tests).

---

## 2. Failure Identification
- **Exact Failure Stage**: RTMP Stream Publication (`sendPublishCommand` on CSID 8, Message Type 20, Stream ID 1).
- **Exact Exception / Network Behavior**: `java.net.SocketException: Connection reset` / `Broken pipe` (TCP RST/FIN received from `a.rtmp.youtube.com:1935` immediately upon receiving the AMF0 `publish` packet with an invalid or unauthenticated key).
- **Exact StreamErrorType**: `StreamErrorType.STREAM_KEY_REJECTED` (with underlying fallback `StreamErrorType.BROKEN_PIPE_PREMATURE_CLOSE`).
- **UI Trigger**: `StreamPipeline.kt` caught repeated socket disconnects during the 3-attempt reconnection manager window, mapped the network exception, and dispatched `CreatorErrorNotifier.postError(...)` which rendered the "Streaming Interrupted" card on the Dashboard.

## 3. Stream Key Lifecycle Audit
1. **Input & UI Layer** (`SettingsFragment.kt`):
   - Text input into `etStreamKey` and `etServerUrl`.
   - Hardening added: Settings auto-persisted on fragment `onPause()` to prevent unsaved credentials when switching tabs.
2. **Encrypted Persistence** (`StreamSettingsRepository.kt` & `SecureCredentialStorage.kt`):
   - Stream key encrypted with AES-256-GCM using Android KeyStore master key (with authenticated app-scoped fallback for test environments).
   - Zero plaintext persistence on disk (`KEY_LEGACY_STREAM_KEY` wiped upon migration).
   - Character preservation: UTF-8 encoding preserves hyphens, underscores, and alphanumeric tokens verbatim.
3. **Validation Boundary** (`StreamConfigurationValidator.kt`):
   - Verifies URL scheme (`rtmp://` or `rtmps://`), host boundaries (RFC limits), port boundaries, and CRLF / control character absence.
   - Non-blank stream key requirement.
4. **Service Dispatch** (`FairyStreamService.kt`):
   - Loads settings from `StreamSettingsRepository.loadSettings()`.
   - Validates configuration; maps any pre-connection failure to `StreamErrorType.EMPTY_STREAM_KEY` or `StreamErrorType.MALFORMED_URL`.
5. **Protocol Ingestion** (`RtmpClient.kt`):
   - Decomposes endpoint into Host (`a.rtmp.youtube.com`), Port (`1935`), App (`live2`), Stream Key (`endpoint.streamKey`).
   - Automatically trims leading/trailing whitespace.
6. **Publish Dispatch** (`RtmpClient.kt` -> `RtmpChunkWriter.kt`):
   - Sends `releaseStream(streamKey)` and `FCPublish(streamKey)` on CSID 3.
   - Sends `publish(streamKey, "live")` on CSID 8.
7. **Logging Audit**:
   - Confirmed zero plaintext logging in Logcat, crash dumps, or error dialogs. Only `StreamDiagnosticInfo` (prefix of 2 chars if length >= 4, length, present boolean) is surfaced.

## 4. RTMP Negotiation Audit
- **Handshake**: Standard C0+C1 (1536 bytes random payload, timestamp 0) -> S0+S1 -> C2 (echo of S1) -> S2 (echo of C1). Verified compliant against YouTube Live ingest (`a.rtmp.youtube.com:1935`).
- **Set Chunk Size**: Client chunk size updated to 4096 bytes via CSID 2, Message Type 1.
- **Connect Command**:
  - `app`: `"live2"` (matching YouTube Live app name).
  - `flashVer`: `"FMLE/3.0 (compatible; FairyLive)"`.
  - `tcUrl`: `"rtmp://a.rtmp.youtube.com/live2"` (dynamic based on endpoint).
  - Result: YouTube returns `NetConnection.Connect.Success`.
- **CreateStream Command**:
  - Sent on CSID 3, Transaction ID 4.0.
  - Result: YouTube returns Stream ID `1.0`.
- **Publish Command**:
  - Message Type: 20 (AMF0 command) on CSID 8, Stream ID 1.
  - Arguments: `publish`, TxID `5.0`, `null`, `streamKey` (verbatim string), `"live"`.
  - YouTube Behavior: If stream key is valid, YouTube initiates ingest. If stream key is invalid/unrecognized, YouTube immediately closes the TCP socket with FIN/RST.
