1. IMPLEMENTATION SUMMARY
==================================================
Milestone 10 integrates real-time camera capture (Face Cam) into FAIRY LIVE's decoupled broadcast compositing pipeline using native Android Camera2 APIs and GPU texture mapping.

Key architectural achievements:
- 100% pure Kotlin native implementation with zero external streaming or camera dependencies (pure Camera2 + OpenGL ES 2.0; CameraX prohibited and avoided).
- Zero-copy GPU live composition path: camera frames flow directly from CameraCaptureSession to an Android Surface backed by an OpenGL SurfaceTexture (GL_TEXTURE_EXTERNAL_OES). There are zero CPU pixel readbacks, zero Bitmap allocations, and zero CPU format conversions in the frame delivery loop.
- Decoupled stream compositor: Facecam PIP renders directly into the outgoing MediaCodec input Surface, keeping creator dashboard controls completely separate from the broadcast feed.
- Low-end optimization: preview resolution is constrained to an optimal 640x480 dimension (pure Kotlin CameraSize) rather than full sensor resolutions (12MP/4K), conserving GPU memory bandwidth and texture fill-rate.
- Sequential switching lifecycle: dedicated background thread (FairyCameraThread) executes sequential teardown (STOP -> CLOSE_SESSION -> CLOSE_DEVICE -> RELEASE -> SELECT -> OPEN -> CONFIGURE -> START) preventing driver deadlocks.
- IPC & Dashboard controls: Creator controls for Facecam toggle, lens switching, and state telemetry, backed by exported StreamControlReceiver for external automation.

3. CAMERA2 ARCHITECTURE
==================================================
The camera subsystem operates on a dedicated HandlerThread ("FairyCameraThread").
- Opening: ContextCompat.checkSelfPermission verified -> CameraManager.openCamera() on background handler.
- Preview Request: CameraDevice.createCaptureRequest(CameraDevice.TEMPLATE_PREVIEW).
- Target Surface: Bound directly to Surface(cameraSurfaceTexture) created on the OpenGL render thread.
- Control Settings: Auto-focus continuous picture (CONTROL_AF_MODE_CONTINUOUS_PICTURE), auto-exposure (CONTROL_AE_MODE_ON).
- Output Configuration: Configured via OutputConfiguration(cameraSurface) or createCaptureSession.
- Driver Safety: All CameraDevice and CameraCaptureSession calls execute strictly sequentially.

==================================================
4. GPU-BASED CAMERA PIPELINE (ZERO-COPY DETAILS)
==================================================
The live frame rendering path is 100% GPU-resident:
1. Physical Camera Sensor -> Camera HAL Driver
2. Hardware Buffer Queue -> Surface (backed by SurfaceTexture)
3. SurfaceTexture.updateTexImage() updates GL_TEXTURE_EXTERNAL_OES on FairyCompositorThread
4. GlesRenderer applies dynamic transforms:
   - uTexMatrix: Automatically absorbs hardware sensor orientation (e.g. 270° front, 90° back)
   - uModel: Scales and translates normalized PIP quad ([0,1] domain), preserving aspect ratio and applying horizontal selfie flip (scaleX = -1.0)
5. Blended in OpenGL ES over background screen capture texture and under graphic overlay layers
6. EGL14.eglSwapBuffers() delivers composited frame directly into MediaCodec video encoder input Surface

Technical Accuracy Note: There is NO CPU pixel copy or readback in this composition loop. We avoid calling it "zero-copy everywhere" across the kernel/HAL boundary, but in the application composition path, it is zero CPU buffer copies.
