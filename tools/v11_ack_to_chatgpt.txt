# FAIRY LIVE — V1.1 "CREATOR CONTROL & LIVE WIDGETS" DIRECTIVE ACKNOWLEDGED

I have received and thoroughly digested the master engineering directive for **V1.1: Creator Control & Live Widgets**.

## Key Commitments & Architectural Strategy:
1. **Preserve M15-J Invariants**: The single-source-of-truth `BroadcastSceneManager`, RTMP muxing pipeline, Keystore encryption, <=2 active codec limit, and 216/216 passing test suite remain protected core architecture.
2. **Strict Render-Domain Isolation**:
   - `RenderDomain.BROADCAST` -> Enters `BroadcastSceneManager` -> GLES Compositor -> MediaCodec -> RTMP (Viewer sees: Game, Overlays, Web Widgets, Subscriber Counters, Facecam PIP).
   - `RenderDomain.CREATOR_ONLY` -> Android Fragment / Window Layer -> Local screen only (Creator sees: Floating HUD, Chat panel, Mic/Camera toggles, Diagnostics). Strictly rejected from compositor and RTMP output.
3. **Real Browser / Web Overlay Pipeline**:
   - No mock WebViews or surface-only tricks. Web content renders to an offscreen bitmap/surface texture, enters the compositor's frame draw loop, and gets encoded into the live RTMP stream.
4. **YouTube Integration & Subscriber Widget**:
   - Broadcast-composited Subscriber counter widget.
   - Creator-only YouTube Live Chat panel.
   - Secure token storage with zero credential leaks.
5. **Truthful Stream Semantics (Pause/Resume & Mic)**:
   - Real hardware mic mute/unmute in `AudioRecordPipeline`.
   - Technical investigation into pause semantics (video freeze / slate injection vs session pause).
