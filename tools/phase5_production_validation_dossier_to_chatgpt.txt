## 1. P0 — CAPTURE ISOLATION VERIFICATION
* **Single-App Isolation Architecture**:
  * Implemented `CaptureSource.SINGLE_APP` utilizing Android 14+ / 15 `MediaProjectionConfig` task picker (`RECORD_CONTENT_TASK`).
  * When a creator goes live, Android prompts the system single-app chooser ("Share or record an app"). The creator selects the target game or application (e.g. Chrome, Free Fire, etc.).
  * **Result**: The virtual display binds strictly to the chosen application's task ID. FAIRY LIVE's studio UI, floating HUD, system navigation bars, notification shades, and incoming calls are completely excluded from the video stream at the OS compositor level.
* **Entire Screen Fallback**:
  * For legacy devices or creators who explicitly configure full-screen streaming, `CaptureSource.ENTIRE_SCREEN` uses `MediaProjectionConfig.createConfigForDefaultDisplay()`.
  * Gating verified in `CreatorStudioFragment.kt`, `DashboardFragment.kt`, and `V12Phase5ProductionValidationUnitTest.kt`.

## 2. P0 — BROADCAST PARITY ACROSS ALL 11 OVERLAY TYPES
Every overlay type shares identical geometry and transform calculations between `BroadcastPreviewView.kt` (Android Canvas preview) and `GlesRenderer.kt` (OpenGL ES broadcast compositor):

1. **TEXT**: Aspect ratio 4.0:1, sub-pixel text measurement, opacity & rotation origin at center $(x + w/2, y + h/2)$.
2. **IMAGE**: Preserves source bitmap aspect ratio $(W_{src} / H_{src})$, clamped to normalized viewport, bi-linear filtering.
3. **GIF**: Animated multi-frame playback driven by monotonically increasing PTS timestamps, zero frame skipping.
4. **FACECAM**: Configurable circular mask (`isCircle = true`) or rounded rectangle, optional chroma keying, mirroring, and camera facing toggle.
5. **ALERT**: Aspect ratio 2.5:1, headline + subtext layout, entrance/exit animation alpha multiplied by layer opacity.
6. **QR**: 1:1 aspect ratio square, high-contrast error-corrected QR bitmap, crisp sub-pixel rendering.
7. **LOWER_THIRD**: Aspect ratio 4.0:1, left-anchored typography with brand accent bar.
8. **GOAL**: Aspect ratio 3.0:1, progress bar calculation $(current / target)$ clamped $[0.0, 1.0]$.
9. **WIDGET**: Real-time stats display (FPS, bitrate, viewer count) updated at 1Hz without triggering compositor pipeline re-allocation.
10. **YOUTUBE_SUBSCRIBER**: Dynamic YouTube channel badge with formatted counter.
11. **WEB**: Offscreen WebView rendered to surface texture at 30fps.

* **Lock Badges & Icons**: Visual indicator shown only in the studio preview and Layer Panel.

## 4. P1 — OVERLAY INTERACTION MATRIX VERIFICATION
Verified in `V12Phase5ProductionValidationUnitTest.kt` (16 test methods, 100% pass):
* **Move**: Delta drag updates $(normalizedX, normalizedY)$ with boundary clamping $[0.0, 1.0]$.
* **Scale**: Pinch gesture updates `scale` factor clamped to $[0.1, 5.0]$.
* **Rotate**: Circular gesture updates `rotationDegrees` normalized $[0^\circ, 360^\circ)$.
* **4-Handle Crop**: Modifies `cropLeft`, `cropTop`, `cropRight`, `cropBottom` with minimum 5% window constraint $(cropRight - cropLeft \ge 0.05)$.
* **Lock / Unlock**: When `isLocked = true`, gesture hit testing ignores the element; bounds and transforms cannot be modified by drag, pinch, or rotation.
* **Hide / Show**: `isVisible = false` bypasses rendering in both Preview Canvas and GLES Compositor.
* **Z-Order Reordering**: `BroadcastSceneManager.reorderLayersInActiveScene()` updates layer stack and preserves strict monotonic z-indexing.
* **Delete**: Removes element from active scene and recycles associated texture memory.
* **Persistence**: Serialized to JSON via `SceneStorageManager`, reloaded, and verified identical bit-for-bit.

## 5. P1 — WEB OVERLAYS: CANVAS SCALE VS WEBPAGE ZOOM INDEPENDENCE
* **Separation of Concerns**:
  * **Overlay Transform**: Controls canvas geometry $(w, h, scale, rotationDegrees)$.
  * **Webpage Zoom**: Controls DOM viewport scaling (`OffscreenWebRenderer.setZoom(zoomLevel)` via `WebSettings.textZoom` and CSS transform).
* **Test Verification**: `testWebOverlay_canvasScaleAndWebpageZoomAreIndependent()` proves that adjusting `zoomLevel` from 1.0x to 2.0x changes internal DOM rendering without altering the overlay's $(normalizedWidth, normalizedHeight, scale)$ on canvas or broadcast stream.
