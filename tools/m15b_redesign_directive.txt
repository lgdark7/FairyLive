FAIRY LIVE — M15-B UI/UX REDESIGN DIRECTIVE

STOP.

Before implementing additional editor polish, reassess the current Creator Studio UI from a real end-user perspective.

The current implementation is technically functional, but the UI is too developer/diagnostic-oriented and is NOT sufficiently user-friendly for a consumer live-streaming application.

DO NOT simply add more controls to the existing layout.

REDESIGN THE USER EXPERIENCE.

============================================================
PRODUCT VISION
============================================================

FAIRY LIVE should feel like:

- a professional mobile creator studio
- simple enough for a first-time streamer
- powerful enough for advanced creators
- gaming/streaming focused
- modern
- visually clean
- touch friendly
- fast
- low-end friendly

The user should understand the primary workflow immediately:

OPEN FAIRY LIVE
→ SEE PREVIEW
→ CHOOSE SCENE
→ CUSTOMIZE
→ GO LIVE

Do NOT make users understand encoder internals, codecs, PSS, ABI, CPU architecture, or pipeline terminology to start streaming.

============================================================
CRITICAL UX RULE
============================================================

SEPARATE:

CREATOR EXPERIENCE

from

ENGINEERING / DIAGNOSTICS.

The creator-facing UI must never look like a debug console.

Keep technical diagnostics available under:

Settings
→ Advanced
→ Diagnostics

or a dedicated Diagnostics page.

Do not remove the diagnostics functionality.

Simply stop presenting it as the primary user experience.

============================================================
CREATOR STUDIO — PRIMARY SCREEN
============================================================

The Creator Studio must be centered around the live preview.

Hierarchy:

1. Preview
2. Scene
3. Add/Edit
4. Layers
5. Stream controls
6. Optional performance information

NOT:

1. Hardware information
2. Encoder information
3. FPS counters
4. CPU information
5. Technical state
============================================================
NEW CREATOR STUDIO STRUCTURE
============================================================

Top:

FAIRY LIVE
[OFFLINE / LIVE]

Optional:
[⚙]

Main:

LIVE PREVIEW

The preview should dominate the screen.

Maintain the selected broadcast aspect ratio.

Inside preview:

- game/screen capture
- facecam
- overlays
- text
- widgets
- goals
- alerts

The creator should immediately understand:

"THIS IS WHAT MY VIEWERS WILL SEE."

Avoid oversized buttons.

Allow horizontal scrolling if necessary.

Scene selector should feel like a modern creator application.

============================================================
LOW-END PERFORMANCE
============================================================

IMPORTANT:

This is NOT permission to introduce a heavyweight UI framework.

Remain:

- Native Android
- lightweight
- efficient
- existing architecture compatible

Avoid:

- continuous animated backgrounds
- blur-heavy effects
- expensive shadows everywhere
- excessive Lottie animations
- unnecessary image assets
- high-frequency UI updates

Preview rendering must remain connected to the existing GPU compositor.

============================================================
BROADCAST INVARIANT
============================================================

ABSOLUTELY DO NOT BREAK:

Creator UI
≠
Broadcast composition

The following must NEVER appear in the outgoing stream:

- GO LIVE button
- Layers panel
- Scene buttons
- Settings
- bottom navigation
- HUD UI unless explicitly added as broadcast widget
- editor handles
- selection borders
- resize handles

Only the actual broadcast scene goes to the compositor.

11. Open Layers.
12. Hide/show element.
13. Save scene.
